# راهنمای نصب سایت روی سرور

این راهنما برای کسی است که سایت خانه تجارت عادلانه ایران را روی یک سرور مجازی (VPS) نصب می‌کند و نگه می‌دارد. همهٔ مراحل با Docker انجام می‌شود، پس روی سرور داخل ایران و خارج از ایران یکسان است؛ نکته‌های مخصوص سرور ایرانی در بخش ۴ آمده است.

## نصب خودکار (راه پیشنهادی)

پس از فراهم کردن منابع (بخش ۱) و وصل کردن دامنه به IP سرور (بخش ۳)، کل نصب با یک اسکریپت انجام می‌شود. با SSH وارد سرور شوید و:

**۱. کلید دسترسی به مخزن را بسازید** و خروجی فرمان دوم را در GitHub > مخزن > Settings > Deploy keys > Add deploy key بگذارید (تیک Allow write access را نزنید):

```bash
ssh-keygen -t ed25519 -N "" -f ~/.ssh/id_ed25519
cat ~/.ssh/id_ed25519.pub
```

**۲. کد را بگیرید و نصب را اجرا کنید:**

```bash
apt update && apt install -y git
git clone git@github.com:jafarmrt/fairtrade-iran.git /opt/fairtrade-iran
cd /opt/fairtrade-iran
sudo ./deploy/install.sh
```

اسکریپت فقط دامنه، ایمیل شما، نام کاربری مدیر و اطلاعات SMTP را می‌پرسد (SMTP را می‌شود خالی گذاشت و بعداً تنظیم کرد). بقیه را خودش انجام می‌دهد:

- Docker، git و دیوار آتش را نصب و تنظیم و منطقهٔ زمانی را تهران می‌کند؛
- بررسی می‌کند Docker Hub و PyPI در دسترس‌اند و اگر نبودند (سرور ایرانی) آینهٔ Docker را خودش پیدا و تنظیم می‌کند؛
- فایل `.env` را با رمزهای تصادفی می‌سازد؛
- سایت را می‌سازد و بالا می‌آورد، محتوای اولیه را می‌گذارد و کاربر مدیر با رمز تصادفی می‌سازد (رمز در پایان نمایش داده و در `/root/fairtrade-admin.txt` ذخیره می‌شود)؛
- بررسی می‌کند دامنه به همین سرور می‌رسد و گواهی HTTPS را می‌گیرد و فعال می‌کند.

پیام‌های اسکریپت انگلیسی است، چون بیشتر ترمینال‌ها فارسی را درست نشان نمی‌دهند.

اجرای دوباره بی‌خطر است: مراحل انجام‌شده رد می‌شوند و `.env` و رمزها دست نمی‌خورند. اگر DNS هنوز آماده نبود یا Let's Encrypt در دسترس نبود، سایت بدون HTTPS بالا می‌آید؛ بعداً همان `sudo ./deploy/install.sh` را دوباره بزنید.

پس از نصب، تنظیمات پنل مدیریت (بخش ۸) و کپی پشتیبان بیرون از سرور (بخش ۹) را انجام دهید. **به‌روزرسانی** هم یک فرمان است: `sudo ./deploy/update.sh` (پشتیبان فوری، دریافت کد تازه، ساخت دوباره، افزودن محتوای تازه).

بخش‌های ۴ تا ۷ همین کارها را دستی توضیح می‌دهند؛ برای وقتی است که بخواهید بدانید اسکریپت چه می‌کند یا جایی خطا داد.

سایت از این بخش‌ها ساخته شده که همه با یک فرمان بالا می‌آیند:

| سرویس | کار |
| --- | --- |
| `db` | پایگاه دادهٔ PostgreSQL |
| `web` | خود سایت (Django و Wagtail) |
| `nginx` | دریافت درخواست‌ها، HTTPS و فایل‌های بارگذاری‌شدهٔ عمومی |
| `backup` | پشتیبان‌گیری خودکار روزانه |
| `scheduler` | کارهای روزانه: یادآوری مهلت پرونده‌های عضویت، صدور و یادآوری حق عضویت سالانه، اخطار و تعلیق اعضای بدهکار، کارهای روزانهٔ مجمع عمومی و فروشگاه؛ و هر ۱۰ دقیقه انتشار صفحه‌هایی که در پنل مدیریت زمان‌بندی شده‌اند |
| `certbot-renew` | تمدید خودکار گواهی HTTPS (پس از بخش ۷) |

## ۱. منابع لازم

### برای راه‌اندازی (ضروری)

| منبع | توضیح |
| --- | --- |
| **سرور مجازی (VPS)** | Ubuntu 24.04، دست‌کم ۲ هستهٔ پردازنده، ۴ گیگابایت حافظه، ۴۰ گیگابایت دیسک SSD، یک IP ثابت و دسترسی root با SSH. اگر اسناد و تصاویر زیادی بارگذاری می‌شود، دیسک بیشتر بگیرید. درباره ایران یا خارج، بخش ۲ را ببینید. |
| **دامنه** | مثلاً `fairtrade.ir` (از ایرنیک یا نمایندگانش) یا `.org`. برای اینماد و درگاه پرداخت، دامنهٔ `.ir` به نام خانه یا مدیرعامل کار را ساده‌تر می‌کند. |
| **ایمیل فرستندهٔ سایت (SMTP)** | یک صندوق مثل `no-reply@دامنه` با نشانی سرور SMTP، درگاه، نام کاربری و رمز. سایت با آن اعلان درخواست عضویت، یادآوری‌ها، فراموشی رمز و کد ورود دومرحله‌ای را می‌فرستد. سرویس ایمیل میزبان یا ایمیل سازمانی دامنه بهتر از Gmail است (Gmail از ایران همیشه پایدار نیست و رمز ویژهٔ برنامه می‌خواهد). |
| **دسترسی به مخزن GitHub** | مخزن خصوصی است؛ روی سرور یک Deploy key (کلید فقط‌خواندنی) ساخته و در GitHub ثبت می‌شود (بخش ۵). |
| **جای نگهداری پشتیبان بیرون از سرور** | یک رایانهٔ دیگر یا فضای ذخیره‌سازی ابری. پشتیبانی که فقط روی همان سرور باشد، با از دست رفتن سرور از بین می‌رود. |
| **یک نفر مسئول فنی** | برای نصب، به‌روزرسانی‌ها و بررسی ماهانهٔ پشتیبان‌ها. |

### بعداً و اختیاری

| منبع | چه وقت لازم است |
| --- | --- |
| **سامانهٔ پیامک** (کاوه‌نگار یا sms.ir) | برای پیامک اعلان‌ها و **ورود اعضا با کد پیامکی**. حساب، اعتبار، کلید API و شماره خط. بدون آن سایت فقط ایمیل می‌فرستد. |
| **اینماد** (نماد اعتماد الکترونیکی، از enamad.ir) | پیش‌نیاز درگاه پرداخت ایرانی. ثبت آن چند روز تا چند هفته طول می‌کشد و دامنه و سایت در حال کار می‌خواهد، پس پس از راه‌اندازی درخواست دهید. |
| **درگاه پرداخت** (زرین‌پال یا آیدی‌پی) | برای پرداخت آنلاین فروشگاه، حق عضویت و هزینهٔ درخواست. پس از اینماد، کد پذیرنده (merchant) می‌گیرید. تا آن موقع پرداخت با واریز به حساب و بارگذاری رسید انجام می‌شود و سایت کامل کار می‌کند. |
| **مجوز فونت IRANSans** | فونت برند. تا آن موقع فونت رایگان وزیرمتن نمایش داده می‌شود. |

## ۲. سرور ایران یا خارج؟

کد برای هر دو آماده است و با پشتیبان کامل (بخش ۱۰) می‌شود بعداً بدون تغییر کد جابه‌جا شد.

| | سرور داخل ایران | سرور خارج از ایران |
| --- | --- | --- |
| سرعت برای کاربران داخل ایران | بهتر | کندتر |
| هنگام اختلال یا قطع اینترنت بین‌الملل | سایت برای کاربران داخل ایران باز می‌ماند | سایت برای کاربران داخل ایران باز نمی‌شود |
| درگاه پرداخت ایرانی (زرین‌پال، آیدی‌پی) | بدون مشکل | معمولاً درخواست از IP خارجی را نمی‌پذیرند |
| سامانهٔ پیامک ایرانی | بدون مشکل | ممکن است IP خارجی را نپذیرد (پیش از اتکا آزمایش کنید) |
| اینماد | عادی | ممکن است سؤال‌برانگیز باشد |
| دسترسی خریداران خارجی | ممکن است کند یا گاهی قطع باشد | خوب |
| گواهی HTTPS رایگان (Let's Encrypt) | کار می‌کند، ولی هنگام قطع اینترنت بین‌الملل تمدید عقب می‌افتد | بدون دردسر |
| نصب و به‌روزرسانی | به‌خاطر تحریم، آینهٔ Docker لازم است (بخش ۴) | بدون دردسر |

**پیشنهاد:** چون پرداخت و پیامک ایرانی است و مخاطب اصلی داخل ایران است، **سرور ایرانی**. میزبان‌هایی که VPS اوبونتو با IP ثابت و پشتیبانی می‌دهند فراوان‌اند (مثلاً ابرآروان، پارس‌پک، آسیاتک و…)؛ پیش از خرید بپرسید آینهٔ Docker دارند یا نه.

## ۳. دامنه و DNS

در پنل دامنه دو رکورد بسازید که به IP سرور اشاره کنند:

| نوع | نام | مقدار |
| --- | --- | --- |
| A | `@` (خود دامنه) | IP سرور |
| A | `www` | IP سرور |

چند دقیقه تا چند ساعت طول می‌کشد تا رکوردها همه‌جا دیده شوند. با `ping example.ir` بررسی کنید که به IP درست می‌رسد.

> در این راهنما به‌جای دامنهٔ واقعی `example.ir` نوشته شده؛ همه‌جا آن را با دامنهٔ خودتان عوض کنید.

## ۴. آماده‌سازی سرور

با SSH وارد سرور شوید (`ssh root@IP-سرور`) و این فرمان‌ها را اجرا کنید.

### به‌روزرسانی و دیوار آتش

```bash
apt update && apt upgrade -y
apt install -y git ufw
ufw allow OpenSSH
ufw allow 80/tcp
ufw allow 443/tcp
ufw enable
timedatectl set-timezone Asia/Tehran
```

### نصب Docker

```bash
apt install -y docker.io docker-compose-v2
systemctl enable --now docker
docker compose version     # باید نسخه‌ای را نشان دهد
```

این بسته‌ها از مخزن خود Ubuntu نصب می‌شوند، پس روی سرور ایرانی هم کار می‌کنند (سایت رسمی Docker، یعنی `download.docker.com`، IPهای ایران را مسدود کرده است).

### فقط برای سرور ایرانی: آینهٔ Docker Hub

Docker Hub هم IPهای ایران را مسدود کرده، پس دریافت ایمیج‌ها (`postgres`، `nginx`، `python`، `certbot`) بدون آینه شکست می‌خورد (خطای `403` یا `denied`). یک آینهٔ ایرانی تنظیم کنید:

```bash
cat > /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": ["https://docker.arvancloud.ir"]
}
EOF
systemctl restart docker
docker pull hello-world    # آزمایش
```

آینه‌ها گاهی عوض یا از کار می‌افتند. اگر این یکی کار نکرد، از پشتیبانی میزبان بپرسید چه آینه‌ای پیشنهاد می‌کند، یا نشانی آینهٔ دیگری را در همان فهرست بگذارید (می‌شود چند نشانی پشت هم نوشت).

اگر نصب بسته‌های پایتون (`pip`) هنگام ساخت سایت خطا داد یا خیلی کند بود، نشانی آینهٔ PyPI را در فایل `.env` بگذارید (بخش ۵):

```
PIP_INDEX_URL=https://نشانی-آینه/simple
```

### روی سرور خارج از ایران

آینه لازم نیست؛ بقیهٔ مراحل یکسان است.

## ۵. دریافت کد و تنظیمات

### دریافت کد

```bash
ssh-keygen -t ed25519 -N "" -f ~/.ssh/id_ed25519
cat ~/.ssh/id_ed25519.pub
```

خروجی را در GitHub، در صفحهٔ مخزن > Settings > Deploy keys > Add deploy key بگذارید (تیک Allow write access را نزنید). سپس:

```bash
cd /opt
git clone git@github.com:jafarmrt/fairtrade-iran.git
cd fairtrade-iran
cp .env.example .env
```

### پر کردن `.env`

دو مقدار تصادفی بسازید:

```bash
openssl rand -base64 48    # برای SECRET_KEY
openssl rand -hex 24       # برای POSTGRES_PASSWORD (فقط حروف و عدد، چون داخل نشانی پایگاه داده می‌رود)
```

سپس فایل را باز کنید (`nano .env`) و این‌ها را پر کنید:

| متغیر | مقدار |
| --- | --- |
| `SECRET_KEY` | رشتهٔ تصادفی اول |
| `ALLOWED_HOSTS` | `example.ir,www.example.ir` |
| `CSRF_TRUSTED_ORIGINS` | `https://example.ir,https://www.example.ir` |
| `SITE_URL` | `https://example.ir` (پیوندهای ایمیل‌ها از این ساخته می‌شود) |
| `USE_HTTPS` | `1` |
| `POSTGRES_PASSWORD` | رشتهٔ تصادفی دوم |
| `EMAIL_HOST`، `EMAIL_PORT`، `EMAIL_HOST_USER`، `EMAIL_HOST_PASSWORD`، `EMAIL_USE_TLS` | اطلاعات SMTP از بخش ۱ (معمولاً درگاه `587` با `EMAIL_USE_TLS=1`) |
| `DEFAULT_FROM_EMAIL` | نشانی فرستنده، مثلاً `no-reply@example.ir` |
| `BACKUP_TIME`، `BACKUP_KEEP_DAYS` | ساعت پشتیبان روزانه (پیش‌فرض `03:30`) و چند روز روی سرور بماند (پیش‌فرض `14`) |
| `DAILY_JOBS_TIME` | ساعت کارهای روزانه (پیش‌فرض `08:00`) |
| `PUBLISH_EVERY_MINUTES` | هر چند دقیقه صفحه‌های زمان‌بندی‌شده منتشر شوند (پیش‌فرض `10`) |

متغیرهای اختیاری (اگر نمی‌دانید، خالی بگذارید):

| متغیر | کار |
| --- | --- |
| `SMS_API_KEY` | کلید API سامانهٔ پیامک، اگر نمی‌خواهید در پنل مدیریت ذخیره شود |
| `PAYMENT_MERCHANT_ID` | کد پذیرندهٔ درگاه پرداخت، اگر نمی‌خواهید در پنل مدیریت ذخیره شود |
| `TWO_FACTOR_DISABLED` | فقط برای موقعیت اضطراری؛ بخش ۸ را ببینید |
| `IMAGES_WEBP` | با `0`، تصاویر به WebP (کم‌حجم‌تر برای اینترنت همراه) تبدیل نمی‌شوند |
| `PIP_INDEX_URL` | آینهٔ PyPI (بخش ۴) |

`.env` رمزها را نگه می‌دارد. آن را هرگز در گیت نگذارید و جایی نفرستید.

> چیزهایی مثل حق عضویت، شمارهٔ حساب، لوگو، اطلاعات تماس، سامانهٔ پیامک و درگاه پرداخت در `.env` نیستند؛ همه از پنل مدیریت تنظیم می‌شوند (بخش ۸).

## ۶. راه‌اندازی اول

```bash
docker compose up -d --build --wait    # تا آماده شدن سایت صبر می‌کند (بار اول چند دقیقه)
docker compose ps                      # همه باید Up باشند
docker compose exec web python manage.py seed_content
docker compose exec web python manage.py createsuperuser
```

`seed_content` صفحه‌های اولیه (فارسی و انگلیسی)، زبان‌ها، لوگوها، گروه‌های کاربری (دبیرخانه، کمیسیون نظارتی، هیئت مدیره، روابط عمومی، اعضا)، مجموعه‌های اسناد، متن ایمیل‌ها و پیامک‌ها را می‌سازد. اجرای دوباره‌اش بی‌خطر است و چیزی را که در پنل ویرایش شده بازنویسی نمی‌کند.

حالا `http://example.ir/` باید باز شود (هنوز بدون قفل HTTPS). تا HTTPS راه نیفتاده، ورود به پنل مدیریت کار نمی‌کند، چون کوکی‌ها فقط روی HTTPS فرستاده می‌شوند.

## ۷. فعال کردن HTTPS

گواهی رایگان Let's Encrypt گرفته می‌شود و خودکار تمدید می‌شود. یک بار اجرا کنید (ایمیل برای هشدارهای انقضا است):

```bash
./deploy/init-https.sh admin@example.ir example.ir www.example.ir
```

اگر پیام `Certificate saved` آمد، این خط را به آخر `.env` اضافه کنید:

```
COMPOSE_FILE=docker-compose.yml:docker-compose.https.yml
```

و سایت را دوباره بالا بیاورید:

```bash
docker compose up -d --wait
```

حالا `https://example.ir/` با قفل باز می‌شود و `http://` خودکار به `https://` می‌رود. پنل مدیریت در `https://example.ir/admin/` است.

**تمدید خودکار:** سرویس `certbot-renew` روزی دو بار بررسی می‌کند و ۳۰ روز مانده به انقضا گواهی را تمدید می‌کند؛ nginx هر ۶ ساعت گواهی تازه را می‌خواند.

**اگر گرفتن گواهی شکست خورد:**

- مطمئن شوید DNS به همین سرور اشاره می‌کند و `http://example.ir/` باز می‌شود.
- Let's Encrypt برای تأیید باید از خارج از ایران به درگاه ۸۰ سرور برسد. هنگام اختلال اینترنت بین‌الملل یا اگر میزبان ترافیک ورودی خارجی را بسته باشد، این کار نمی‌شود. بعداً دوباره امتحان کنید یا از میزبان بپرسید. گواهی ۹۰ روزه است و تمدید از ۳۰ روز مانده شروع می‌شود، پس قطعی چندروزه مشکلی درست نمی‌کند.
- راه دیگر: CDN ایرانی (مثل ابرآروان) که HTTPS را خودش جلوی سایت فراهم می‌کند، یا خرید گواهی تجاری. فایل‌های گواهی باید با نام‌های `fullchain.pem` و `privkey.pem` در مسیر `/etc/letsencrypt/live/site/` حجم `letsencrypt` قرار بگیرند.

## ۸. تنظیمات پنل مدیریت

با کاربر مدیر وارد `https://example.ir/admin/` شوید. همه‌چیز زیر منوی **تنظیمات** است:

| بخش | چه چیزی |
| --- | --- |
| تنظیمات سایت | نام و شعار به دو زبان، لوگوها، اطلاعات تماس، شبکه‌های اجتماعی، ایمیل دبیرخانه برای اعلان‌ها، نمایش قیمت به تومان یا ریال |
| تنظیمات عضویت | هزینهٔ درخواست و حق عضویت سالانه برای هر نوع عضو، شمارهٔ حساب، مهلت‌ها، دورهٔ آزمایشی، باز یا بسته بودن پذیرش؛ و در زبانهٔ «حق عضویت سالانه و تعلیق»، سال عضویت، یادآوری، اخطار و تعلیق |

| تنظیمات پرداخت آنلاین | درگاه (زرین‌پال یا آیدی‌پی)، کد پذیرنده، روشن یا خاموش. **تا اینماد و درگاه ندارید خاموش بماند**؛ پرداخت با واریز و رسید کار می‌کند |

سپس زیر **تنظیمات > کاربران** برای اعضای دبیرخانه، کمیسیون، هیئت مدیره و روابط عمومی کاربر بسازید و هر کدام را در گروه خودش بگذارید. دسترسی‌ها (کنترل مدارک، رأی کمیسیون، اسناد محرمانه، تأیید محتوای روابط عمومی) از گروه می‌آید.

### پیامک

ارسال پیامک در ابتدا خاموش است و سایت فقط ایمیل می‌فرستد. برای روشن کردن:

1. در کاوه‌نگار یا sms.ir حساب بسازید، اعتبار بخرید و کلید API و شماره خط را بگیرید.
2. در «تنظیمات > تنظیمات پیامک» سامانه، کلید API (یا `SMS_API_KEY` در `.env`)، شماره خط و شماره همراه دبیرخانه و کمیسیون را وارد کنید و «ارسال پیامک فعال است» را بزنید.
3. از منوی «پیامک > ارسال آزمایشی و گزارش» یک پیامک آزمایشی به شمارهٔ خودتان بفرستید. اگر نرسید، علت خطا در همان صفحه نوشته می‌شود.
4. متن هر پیامک و روشن یا خاموش بودنش در «پیامک > متن‌های پیامک» ویرایش می‌شود.

ورود اعضا به پنل با کد پیامکی فقط وقتی کار می‌کند که پیامک روشن باشد.

### پرداخت آنلاین (پس از اینماد)

1. با سایت در حال کار، از enamad.ir اینماد بگیرید و کد نماد را در «سئو، آمار و نمادها» بگذارید.
2. در زرین‌پال یا آیدی‌پی درگاه بگیرید و نشانی سایت (`https://example.ir`) را ثبت کنید.
3. در «تنظیمات پرداخت آنلاین» درگاه و کد پذیرنده را وارد کنید. اول «حالت آزمایشی (سندباکس) درگاه» را روشن کنید و یک خرید آزمایشی انجام دهید؛ اگر درست بود، حالت آزمایشی را خاموش و پرداخت آنلاین را روشن کنید.

### امنیت

- در «تنظیمات > امنیت» ورود دومرحله‌ای کارکنان را روشن کنید: پس از رمز عبور، کدی به ایمیل کاربر فرستاده می‌شود. پیش از روشن کردن، مطمئن شوید ایمیل سایت کار می‌کند و همهٔ کاربران مدیریت ایمیل درست دارند.
- اگر ایمیل خراب شد و کسی نتوانست وارد شود: در `.env` خط `TWO_FACTOR_DISABLED=1` را بگذارید، `docker compose up -d` بزنید، وارد شوید و مشکل ایمیل را حل کنید؛ سپس آن خط را پاک کنید و دوباره `docker compose up -d` بزنید.
- سیاست امنیت محتوا (CSP) به‌طور پیش‌فرض فعال است. نشانی‌های «کد آمار بازدید» و «کد نمادهای اعتماد» خودکار مجازند؛ اگر سرویس دیگری کار نکرد، نشانی‌اش را در همان صفحه به فهرست نشانی‌های مجاز بیفزایید.
- پس از چند ورود ناموفق پیاپی، ورود برای آن نام کاربری یا نشانی اینترنتی ۱۵ دقیقه بسته می‌شود.

## ۹. پشتیبان‌گیری

سرویس `backup` هر روز در ساعت `BACKUP_TIME` (و یک بار هم هر بار که روشن می‌شود) این‌ها را در پوشهٔ `backups/` کنار کد می‌گذارد:

| فایل | محتوا |
| --- | --- |
| `db.dump` | کل پایگاه داده: صفحه‌ها، اعضا، پرونده‌ها، سفارش‌ها، رأی‌ها، تنظیمات |
| `media.tar.gz` | تصاویر و فایل‌های عمومی |
| `private_media.tar.gz` | مدارک درخواست‌های عضویت، رسیدها و اسناد بایگانی |

هر روز یک پوشه با نام تاریخ ساخته می‌شود (مثلاً `backups/2026-11-02_0330/`) و پوشه‌های قدیمی‌تر از `BACKUP_KEEP_DAYS` روز پاک می‌شوند.

```bash
ls -l backups/
docker compose logs backup | tail
docker compose run --rm backup now     # یک پشتیبان فوری، مثلاً پیش از به‌روزرسانی
```

### کپی بیرون از سرور (مهم)

دست‌کم هفته‌ای یک بار پوشهٔ `backups/` را جای دیگری کپی کنید. ساده‌ترین راه، از یک رایانهٔ دیگر (لینوکس یا مک):

```bash
rsync -av root@IP-سرور:/opt/fairtrade-iran/backups/ ./fairtrade-backups/
```

برای خودکار کردنش همین فرمان را در `crontab` آن رایانه بگذارید، یا از `rclone` برای فرستادن به فضای ابری استفاده کنید. پشتیبان‌ها مدارک شخصی متقاضیان را دارند؛ آن‌ها را فقط جایی نگه دارید که دسترسی‌اش محدود است.

## ۱۰. بازگردانی از پشتیبان

این کار **پایگاه داده و فایل‌های فعلی را جایگزین** می‌کند. پیش از آن، اگر سایت هنوز کار می‌کند، یک پشتیبان فوری بگیرید.

```bash
cd /opt/fairtrade-iran
ls backups/
./deploy/restore.sh backups/2026-11-02_0330
```

اسکریپت تأیید می‌خواهد (`yes`)، سایت را چند ثانیه متوقف می‌کند، داده‌ها را برمی‌گرداند و دوباره روشن می‌کند.

**انتقال به سرور تازه:** مراحل ۴ تا ۶ را روی سرور جدید انجام دهید (بدون `seed_content` و `createsuperuser`)، پوشهٔ پشتیبان را به `backups/` سرور جدید کپی کنید، `restore.sh` را اجرا کنید، DNS را به IP جدید عوض کنید و مرحلهٔ ۷ را انجام دهید.

هر چند ماه یک بار بازگردانی را روی یک سرور آزمایشی امتحان کنید تا مطمئن شوید پشتیبان‌ها سالم‌اند.

## ۱۱. به‌روزرسانی سایت

وقتی تغییر تازه‌ای در شاخهٔ `main` گیت‌هاب قرار گرفت و تیک سبز آزمون‌ها را داشت:

```bash
cd /opt/fairtrade-iran
sudo ./deploy/update.sh
```

اسکریپت به‌ترتیب این کارها را می‌کند: `docker compose run --rm backup now`، `git pull`، `docker compose up -d --build --wait` ، `seed_content` و `update_index` (تازه کردن فهرست جست‌وجو).

تغییرات پایگاه داده (migration) هنگام روشن شدن سایت خودکار اجرا می‌شود. `seed_content` فقط چیزهای تازه (مثلاً متن ایمیل یا صفحهٔ جدید) را اضافه می‌کند.

## ۱۲. فرمان‌های کاربردی

| کار | فرمان |
| --- | --- |
| وضعیت سرویس‌ها | `docker compose ps` |
| دیدن خطاهای سایت | `docker compose logs -f web` |
| راه‌اندازی دوبارهٔ سایت | `docker compose restart web` |
| ساختن کاربر مدیر تازه | `docker compose exec web python manage.py createsuperuser` |
| تغییر رمز یک کاربر | `docker compose exec web python manage.py changepassword نام-کاربری` |
| اجرای فوری کارهای روزانه | `docker compose exec scheduler sh /app/deploy/scheduler.sh now` |
| گزارش کارهای روزانه | `docker compose logs scheduler \| tail` |
| فضای دیسک | `df -h` و `du -sh backups/` |
| خاموش کردن همه | `docker compose down` (داده‌ها پاک نمی‌شوند) |

> هرگز `docker compose down -v` نزنید: `-v` حجم‌های پایگاه داده و فایل‌ها را **پاک می‌کند**.
