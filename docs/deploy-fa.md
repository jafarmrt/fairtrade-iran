# راهنمای استقرار سایت روی سرور

این راهنما برای کسی است که سایت خانه تجارت عادلانه ایران را روی یک سرور مجازی (VPS) راه می‌اندازد و نگه می‌دارد. همهٔ مراحل با Docker انجام می‌شود، پس روی سرور داخل ایران و خارج از ایران یکسان است؛ فقط چند نکتهٔ مخصوص سرور ایرانی در بخش ۳ آمده است.

سایت از چهار بخش ساخته شده که همه با یک فرمان بالا می‌آیند:

| سرویس | کار |
| --- | --- |
| `db` | پایگاه دادهٔ PostgreSQL |
| `web` | خود سایت (Django و Wagtail) |
| `nginx` | دریافت درخواست‌ها، HTTPS و فایل‌های بارگذاری‌شدهٔ عمومی |
| `backup` | پشتیبان‌گیری خودکار روزانه |

---

## ۱. انتخاب سرور: ایران یا خارج؟

این تصمیم هنوز گرفته نشده و کد برای هر دو آماده است. خلاصهٔ مقایسه:

| | سرور داخل ایران | سرور خارج از ایران |
| --- | --- | --- |
| سرعت برای کاربران داخل ایران | بهتر | کندتر |
| در دسترس بودن هنگام اختلال اینترنت بین‌الملل | سایت برای کاربران داخل ایران باز می‌ماند | سایت برای کاربران داخل ایران باز نمی‌شود |
| درگاه پرداخت ایرانی (شاپرک) | معمولاً بدون مشکل | بیشتر درگاه‌ها سرور خارجی را نمی‌پذیرند |
| دسترسی خریداران خارجی | ممکن است کند یا گاهی قطع باشد | خوب |
| نصب و به‌روزرسانی | به‌خاطر تحریم، به آینه (mirror) نیاز دارد (بخش ۳) | بدون دردسر |

پیشنهاد: چون فروشگاه و درگاه پرداخت ایرانی و مخاطب اصلی داخل ایران است، **سرور ایرانی** گزینهٔ طبیعی‌تر است. اگر بعداً خواستید، می‌توانید با یک پشتیبان کامل (بخش ۸) سایت را بدون تغییر کد به سرور دیگری ببرید.

**مشخصات پیشنهادی سرور:** Ubuntu 24.04، دست‌کم ۲ هستهٔ پردازنده، ۴ گیگابایت حافظه (۲ گیگ هم کار می‌کند)، ۴۰ گیگابایت دیسک SSD. اگر اسناد و تصاویر زیادی بارگذاری می‌شود، دیسک بیشتر بگیرید.

---

## ۲. دامنه و DNS

در پنل دامنه (مثلاً ایرنیک برای `.ir`) دو رکورد بسازید که به IP سرور اشاره کنند:

| نوع | نام | مقدار |
| --- | --- | --- |
| A | `@` (خود دامنه) | IP سرور |
| A | `www` | IP سرور |

چند دقیقه تا چند ساعت طول می‌کشد تا رکوردها همه‌جا دیده شوند. با `ping example.ir` بررسی کنید که به IP درست می‌رسد.

> در این راهنما به‌جای دامنهٔ واقعی `example.ir` نوشته شده؛ همه‌جا آن را با دامنهٔ خودتان عوض کنید.

## ۳. آماده‌سازی سرور

با SSH وارد سرور شوید (`ssh root@IP-سرور`) و این فرمان‌ها را اجرا کنید.

### به‌روزرسانی و دیوار آتش

```bash
apt update && apt upgrade -y
apt install -y git ufw
ufw allow OpenSSH
ufw allow 80/tcp
ufw allow 443/tcp
ufw enable
```

### نصب Docker

```bash
apt install -y docker.io docker-compose-v2
systemctl enable --now docker
docker compose version     # باید نسخه‌ای را نشان دهد
```

این بسته‌ها از مخزن خود Ubuntu نصب می‌شوند، پس روی سرور ایرانی هم کار می‌کنند (سایت رسمی Docker، یعنی `download.docker.com`، IPهای ایران را مسدود کرده است).

### فقط برای سرور ایرانی: آینهٔ Docker Hub

Docker Hub هم IPهای ایران را مسدود کرده، پس دریافت ایمیج‌ها (`postgres`، `nginx`، `python`، `certbot`) بدون آینه شکست می‌خورد (خطای `403` یا `denied`). یک آینهٔ ایرانی تنظیم کنید:

```bash
cat > /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": ["https://docker.arvancloud.ir"]
}
EOF
systemctl restart docker
docker pull hello-world    # آزمایش
```

آینه‌ها گاهی عوض یا از کار می‌افتند. اگر این یکی کار نکرد، از پشتیبانی شرکت میزبانی بپرسید چه آینه‌ای پیشنهاد می‌کند، یا نشانی آینهٔ دیگری را در همان فهرست بگذارید (می‌شود چند نشانی پشت هم نوشت).

اگر نصب بسته‌های پایتون (`pip`) هنگام ساخت سایت خطا داد یا خیلی کند بود، نشانی آینهٔ PyPI را در فایل `.env` بگذارید (بخش ۴):

```
PIP_INDEX_URL=https://نشانی-آینه/simple
```

### روی سرور خارج از ایران

هیچ‌کدام از کارهای بالا لازم نیست؛ می‌توانید Docker را از مخزن رسمی هم نصب کنید.

## ۴. دریافت کد و تنظیمات

مخزن خصوصی است. ساده‌ترین راه، ساختن یک **Deploy key** (کلید فقط‌خواندنی) برای همین سرور است:

```bash
ssh-keygen -t ed25519 -N "" -f ~/.ssh/id_ed25519
cat ~/.ssh/id_ed25519.pub
```

خروجی را در GitHub، در صفحهٔ مخزن > Settings > Deploy keys > Add deploy key بگذارید (تیک Allow write access را نزنید). سپس:

```bash
cd /opt
git clone git@github.com:jafarmrt/fairtrade-iran.git
cd fairtrade-iran
cp .env.example .env
```

### پر کردن `.env`

دو مقدار تصادفی بسازید:

```bash
openssl rand -base64 48    # برای SECRET_KEY
openssl rand -hex 24       # برای POSTGRES_PASSWORD (فقط حروف و عدد، چون داخل نشانی پایگاه داده می‌رود)
```

سپس فایل را باز کنید (`nano .env`) و این‌ها را پر کنید:

| متغیر | مقدار |
| --- | --- |
| `SECRET_KEY` | رشتهٔ تصادفی اول |
| `ALLOWED_HOSTS` | `example.ir,www.example.ir` |
| `CSRF_TRUSTED_ORIGINS` | `https://example.ir,https://www.example.ir` |
| `SITE_URL` | `https://example.ir` |
| `USE_HTTPS` | `1` |
| `POSTGRES_PASSWORD` | رشتهٔ تصادفی دوم |
| `EMAIL_*` و `DEFAULT_FROM_EMAIL` | اطلاعات SMTP برای ارسال ایمیل (اعلان درخواست عضویت و فراموشی رمز) |
| `SMS_API_KEY` | اختیاری: کلید API سامانه پیامک، اگر نمی‌خواهید در پنل مدیریت ذخیره شود |
| `BACKUP_TIME` | ساعت پشتیبان‌گیری روزانه به وقت تهران، پیش‌فرض `03:30` |
| `BACKUP_KEEP_DAYS` | چند روز پشتیبان روی سرور بماند، پیش‌فرض `14` |

`.env` رمزها را نگه می‌دارد. آن را هرگز در گیت نگذارید و جایی نفرستید (در `.gitignore` آمده است).

> چیزهایی مثل حق عضویت، شمارهٔ حساب، لوگو و اطلاعات تماس در `.env` نیستند؛ همه از پنل مدیریت سایت تنظیم می‌شوند.

## ۵. راه‌اندازی اول

```bash
docker compose up -d --build --wait    # تا آماده شدن سایت صبر می‌کند (بار اول تا یکی دو دقیقه)
docker compose ps                      # همه باید Up باشند
docker compose exec web python manage.py seed_content
docker compose exec web python manage.py createsuperuser
```

`seed_content` صفحه‌های اولیه، زبان‌ها، لوگوها، گروه‌های کاربری و مجموعه‌های اسناد را می‌سازد. اجرای دوباره‌اش بی‌خطر است و چیزی را که در پنل ویرایش شده بازنویسی نمی‌کند.

### پیامک (اختیاری)

ارسال پیامک در ابتدا خاموش است و سایت فقط ایمیل می‌فرستد. برای روشن کردن آن:

1. در یکی از سامانه‌های پیامک (کاوه‌نگار یا sms.ir) حساب بسازید، اعتبار بخرید و کلید API و شماره خط را بگیرید.
2. در پنل مدیریت به «تنظیمات > تنظیمات پیامک» بروید، سامانه، کلید API (یا متغیر `SMS_API_KEY` در `.env`)، شماره خط و شماره همراه دبیرخانه و کمیسیون را وارد کنید و «ارسال پیامک فعال است» را بزنید.
3. از منوی «پیامک > ارسال آزمایشی و گزارش» یک پیامک آزمایشی به شماره خودتان بفرستید. اگر نرسید، علت خطا در همان صفحه نوشته می‌شود.
4. متن هر پیامک و روشن یا خاموش بودنش در «پیامک > متن‌های پیامک» ویرایش می‌شود.

اگر سرور خارج از ایران است، پیش از روشن کردن، با پیامک آزمایشی مطمئن شوید سامانه پیامک درخواست‌های آن سرور را می‌پذیرد.

حالا `http://example.ir/` باید باز شود (هنوز بدون قفل HTTPS). تا HTTPS راه نیفتاده، ورود به پنل مدیریت کار نمی‌کند، چون کوکی‌ها فقط روی HTTPS فرستاده می‌شوند.

## ۶. فعال کردن HTTPS

گواهی رایگان Let's Encrypt گرفته می‌شود و خودکار تمدید می‌شود. یک بار اجرا کنید (ایمیل برای هشدارهای انقضا است):

```bash
./deploy/init-https.sh admin@example.ir example.ir www.example.ir
```

اگر پیام `Certificate saved` آمد، این خط را به آخر `.env` اضافه کنید:

```
COMPOSE_FILE=docker-compose.yml:docker-compose.https.yml
```

و سایت را دوباره بالا بیاورید:

```bash
docker compose up -d
```

حالا `https://example.ir/` با قفل باز می‌شود و `http://` خودکار به `https://` می‌رود. پنل مدیریت در `https://example.ir/admin/` است.

**تمدید خودکار:** سرویس `certbot-renew` روزی دو بار بررسی می‌کند و ۳۰ روز مانده به انقضا گواهی را تمدید می‌کند؛ nginx هر ۶ ساعت گواهی تازه را می‌خواند. کاری لازم نیست.

**اگر گرفتن گواهی شکست خورد:**

- مطمئن شوید DNS به همین سرور اشاره می‌کند و `http://example.ir/` باز می‌شود.
- Let's Encrypt برای تأیید باید از خارج از ایران به درگاه ۸۰ سرور برسد. هنگام اختلال اینترنت بین‌الملل یا اگر میزبان ترافیک ورودی خارجی را بسته باشد، این کار نمی‌شود. بعداً دوباره امتحان کنید یا از میزبان بپرسید. گواهی ۹۰ روزه است و تمدید از ۳۰ روز مانده شروع می‌شود، پس قطعی چندروزه مشکلی درست نمی‌کند.
- راه دیگر: سرویس CDN ایرانی (مثل ابرآروان) که HTTPS را خودش جلوی سایت فراهم می‌کند، یا خرید گواهی تجاری. در این حالت با نیروی فنی هماهنگ کنید؛ فایل‌های گواهی باید با نام‌های `fullchain.pem` و `privkey.pem` در مسیر `/etc/letsencrypt/live/site/` حجم `letsencrypt` قرار بگیرند.

## ۷. پشتیبان‌گیری

سرویس `backup` هر روز در ساعت `BACKUP_TIME` (و یک بار هم هر بار که روشن می‌شود) این‌ها را در پوشهٔ `backups/` کنار کد می‌گذارد:

| فایل | محتوا |
| --- | --- |
| `db.dump` | کل پایگاه داده: صفحه‌ها، اعضا، درخواست‌ها، تنظیمات |
| `media.tar.gz` | تصاویر و اسناد بارگذاری‌شده |
| `private_media.tar.gz` | مدارک خصوصی درخواست‌های عضویت و رسیدها |

هر روز یک پوشه با نام تاریخ ساخته می‌شود (مثلاً `backups/2026-11-02_0330/`) و پوشه‌های قدیمی‌تر از `BACKUP_KEEP_DAYS` روز پاک می‌شوند.

بررسی:

```bash
ls -l backups/
docker compose logs backup | tail
docker compose run --rm backup now     # یک پشتیبان فوری، مثلاً پیش از به‌روزرسانی
```

### کپی بیرون از سرور (مهم)

پشتیبانی که فقط روی همان سرور است، با خراب شدن یا از دست رفتن سرور از بین می‌رود. دست‌کم هفته‌ای یک بار پوشهٔ `backups/` را جای دیگری کپی کنید. ساده‌ترین راه، از یک رایانهٔ دیگر (لینوکس یا مک):

```bash
rsync -av root@IP-سرور:/opt/fairtrade-iran/backups/ ./fairtrade-backups/
```

برای خودکار کردنش می‌توانید همین فرمان را در `crontab` آن رایانه بگذارید، یا از `rclone` برای فرستادن به یک فضای ذخیره‌سازی ابری استفاده کنید. پوشهٔ `private_media` مدارک شخصی متقاضیان را دارد؛ آن را فقط جایی نگه دارید که دسترسی‌اش محدود است.

## ۸. بازگردانی از پشتیبان

این کار **پایگاه داده و فایل‌های فعلی را جایگزین** می‌کند. پیش از آن، اگر سایت هنوز کار می‌کند، یک پشتیبان فوری بگیرید.

```bash
cd /opt/fairtrade-iran
ls backups/
./deploy/restore.sh backups/2026-11-02_0330
```

اسکریپت تأیید می‌خواهد (`yes`)، سایت را چند ثانیه متوقف می‌کند، داده‌ها را برمی‌گرداند و دوباره روشن می‌کند.

**انتقال به سرور تازه:** مراحل ۳ تا ۵ را روی سرور جدید انجام دهید (بدون `seed_content` و `createsuperuser`)، پوشهٔ پشتیبان را به `backups/` سرور جدید کپی کنید، `restore.sh` را اجرا کنید، DNS را به IP جدید عوض کنید و مرحلهٔ ۶ را انجام دهید.

پیشنهاد می‌شود هر چند ماه یک بار بازگردانی را روی یک سرور آزمایشی امتحان کنید تا مطمئن شوید پشتیبان‌ها سالم‌اند.

## ۹. به‌روزرسانی سایت

وقتی تغییر تازه‌ای در شاخهٔ `main` گیت‌هاب قرار گرفت:

```bash
cd /opt/fairtrade-iran
docker compose run --rm backup now
git pull
docker compose up -d --build --wait
```

تغییرات پایگاه داده (migration) هنگام روشن شدن سایت خودکار اجرا می‌شود. اگر صفحهٔ تازه‌ای به محتوای اولیه اضافه شده، `docker compose exec web python manage.py seed_content` را هم بزنید.

پیش از هر ادغام در `main`، GitHub Actions خودکار آزمون‌ها را اجرا می‌کند و سایت را با Docker می‌سازد و بالا می‌آورد؛ اگر تیک سبز نبود، به‌روزرسانی نکنید.

## ۱۰. فرمان‌های کاربردی

| کار | فرمان |
| --- | --- |
| وضعیت سرویس‌ها | `docker compose ps` |
| دیدن خطاهای سایت | `docker compose logs -f web` |
| راه‌اندازی دوبارهٔ سایت | `docker compose restart web` |
| ساختن کاربر مدیر تازه | `docker compose exec web python manage.py createsuperuser` |
| تغییر رمز یک کاربر | `docker compose exec web python manage.py changepassword نام-کاربری` |
| فضای دیسک | `df -h` و `du -sh backups/` |
| خاموش کردن همه | `docker compose down` (داده‌ها پاک نمی‌شوند) |

> هرگز `docker compose down -v` نزنید: `-v` حجم‌های پایگاه داده و فایل‌ها را **پاک می‌کند**.
